# Product Teardown（Founder OS 版）· Fork 说明

Fork 自 [yanliudesign/product-teardown-skill](https://github.com/yanliudesign/product-teardown-skill)（作者声明 MIT，可自由 fork 改造）。

## 为什么 fork

原版是 Principal-PM 级别的拆解框架（JTBD、核心循环、北极星指标推断），思考质量高；但它是为欧美生产力产品（Linear/Notion）设计的，直用在我们的竞品 teardown 管线里有四个问题：截图靠官网 og:image（小程序/App 竞品没有）、无证据纪律（无用户原声、无差评挖掘、无证据强度标注）、单品深挖不横向可比、中英双语对我们是多余工作量。

## 改了什么

**删除**
- 中英双语 → 只出中文
- 品牌 footer（原作者署名与社交媒体链接）
- og:image 截图机制 → 改为用户实拍截图
- 风险矩阵（并入"摩擦 & 弱点"）
- Notion / Linear 填充脚本、翻译脚本

**新增（Founder OS 特有）**
- 证据纪律：每个关键判断标注；推断标 `[推断]`；不编造数字
- 用户原声：第 12 节，好评/差评摘录，原话引用并注明来源；差评归类 Top 3 痛点
- 对我们的启示：第 13 节，可借鉴 / 避雷 / 待验证问题（全部可执行）
- 横向对比矩阵：`comparison-matrix.md`，库级，每拆解一款追加一行
- 附录机制：方向专用视角（如宠物方向补充视角）以附录形式存在，不污染通用框架

**保留**
- 15 节 → 14 节的分析骨架：产品快照、用户 & JTBD、核心循环、架构 & IA、体验质量 & 工艺信号、商业模式 & 变现、增长 & 留存钩子、竞争定位、AI 就绪度、北极星指标推断、摩擦 & 弱点、一句话终评
- "循环 > feature"、"JTBD 比 persona 值钱"、"机会必须可执行"三条设计原则
- HTML 报告交付物（重写为克制风格的中文单语模板）

## 怎么用

见 `SKILL.md`。一句话：用户给"产品名 + 平台 + 实拍截图 + 一句话感受"，agent 补商店信息/差评/公开讨论，输出对话内拆解 + HTML 报告 + 对比矩阵更新。
